# AQUA CREW — Maintenance Recommendation Engine Specification
**Task 09 Technical Documentation — Decision Logic, Human Review & Autonomous Dispatch Bridge**

## 1. Overview

The **Maintenance Recommendation Engine** (`app/services/maintenance_recommendation_service.py`) synthesizes quantitative health scores ($H$), multi-horizon failure probabilities ($P_{24h}, P_{7d}, P_{30d}$), and degradation velocities ($\beta$) into actionable, explainable maintenance directives.

Crucially, the engine serves as the **operational bridge** connecting predictive intelligence with the **Task 08 Autonomous Rover Dispatch System**, while strictly enforcing human-in-the-loop operator review.

---

## 2. Maintenance Action Decision Matrix

| Condition | Recommended Action | Urgency | Timeframe |
| :--- | :--- | :--- | :--- |
| **$P_{24h} \ge 0.50$ OR $H < 25$** | `DISPATCH_INSPECTION_ROVER` | `CRITICAL` | 24 Hours |
| **$P_{7d} \ge 0.40$ OR $H < 50$ OR $\beta < -2.0$** | `DISPATCH_INSPECTION_ROVER` | `HIGH` | 48 Hours |
| **Acoustic Anomaly Spikes $> 2$** | `SCHEDULE_ACOUSTIC_INSPECTION` | `MEDIUM` | 7 Days |
| **Pressure Drop $> 2$ OR $\sigma_P \ge 0.35\text{ bar}$** | `SCHEDULE_PRESSURE_INSPECTION` | `MEDIUM` | 7 Days |
| **$H < 75$ OR $\beta < -0.5$** | `INCREASE_SENSOR_MONITORING` | `MEDIUM` | 14 Days |
| **$H \ge 75$ AND $\beta \ge -0.5$** | `CONTINUE_MONITORING` | `ROUTINE` | 30 Days |

## 3. Human-in-the-Loop Operator Review Protocol

Recommendations generated by the system are placed into `PENDING_REVIEW` status and cannot trigger operational changes without human authorization:

```
                  [System Generates Recommendation]
                  (Status: PENDING_REVIEW, Urgency)
                                  │
                                  ▼
                ┌───────────────────────────────────┐
                │    Human Operator Review Gate     │
                └───────┬───────────┬───────────┬───┘
                        │           │           │
           (ACKNOWLEDGE)│  (DISMISS)│ (DISPATCH)│
                        ▼           ▼           ▼
                 [ACKNOWLEDGED] [DISMISSED] [DISPATCHED]
                                                │
                                                ▼
                                   ┌──────────────────────────┐
                                   │  Task 08 Mission Plan    │
                                   │  (Rover Selection &      │
                                   │   Dijkstra Pipe Routing) │
                                   └────────────┬─────────────┘
                                                │
                                                ▼
                                   ┌──────────────────────────┐
                                   │ Operator Mission Sign-Off│
                                   │ [Approve & Crawl]        │
                                   └──────────────────────────┘
```

### Review Actions:
1. **`ACKNOWLEDGE`**: The operator notes the finding for shift logs or scheduling meetings. Status becomes `ACKNOWLEDGED`.
2. **`DISMISS`**: The operator marks the finding as an expected operational artifact (e.g., hydrant flushing). Status becomes `DISMISSED`.
3. **`DISPATCH`**: The operator authorizes autonomous rover inspection. Status becomes `DISPATCHED`.

---

## 4. Bridge to Task 08 Autonomous Dispatch

When an operator selects **`DISPATCH`**:
1. The service looks up existing AI leak detections on the segment, or instantiates a formal preventive inspection record (`AiDetectionModel`).
2. The service calls `MissionPlanningService.plan_mission_for_detection(db, detection.id, priority_override=rec.urgency)`.
3. Task 08 evaluates candidate rovers (`ROV-AQUA-01`, `02`, `03`, `04`), verifies battery safety margins ($\ge 20\%$), and checks motor temperatures ($< 50^\circ\text{C}$).
4. Dijkstra's shortest-path algorithm calculates connected pipeline polyline waypoints.
5. A `MissionRecommendationModel` is generated in `PENDING_APPROVAL` status and linked via `dispatched_mission_id`.
6. The operator opens `/app/dispatch` to conduct final route inspection and authorize physical virtual rover crawling.

---

## 5. Duplicate Prevention

To prevent recommendation flooding, the service queries existing active recommendations for a segment:
- If a recommendation in `PENDING_REVIEW` or `ACKNOWLEDGED` already exists, subsequent calls return the existing active record rather than creating duplicates.
- Operators can force regeneration by passing `force_regenerate=True` or via `POST /maintenance/recommendations/generate/{segment_id}`.
