> [!IMPORTANT]
> **SIMULATION-FIRST MANDATORY REQUIREMENT**:
> AQUA CREW enforces `HARDWARE_ACTUATION_ENABLED = false` at the architectural, service, and API levels. Task 18 bridges physical IoT edge devices (acoustic loggers, hydrostatic pressure transducers, electromagnetic flow meters, subsurface moisture probes, optical cameras, and industrial gateways) with the AQUA CREW software platform while strictly preserving the simulation-first safety posture.

## 2. Core Architectural Principles

### 2.1 Simulation-First Safety Isolation
- **Global Toggle**: `settings.HARDWARE_ACTUATION_ENABLED = False` is enforced globally in `apps/api/app/config.py`.
- **Domain Interlock**: In `apps/api/app/modules/hardware_gateway/__init__.py`, `HARDWARE_ACTUATION_ENABLED = False` and `HARDWARE_ACTUATORS_DISABLED = True` are immutable architectural constants.
- **Service Verification**: `HardwareSafetyService.verify_operation_safety()` intercepts every command. Any command matching `PROHIBITED_ACTUATION_COMMANDS` or containing actuator keyword stems (`VALVE`, `PUMP`, `ACTUAT`, `RELAY`, `MOTOR_DRIVE`, `SCADA`) immediately raises `HardwareActuationForbiddenException` (HTTP 403 `HARDWARE_ACTUATION_PROHIBITED`).
- **Allowlist Restriction**: Only explicitly allowlisted non-actuating commands (`READ_STATUS`, `REQUEST_TELEMETRY`, `READ_SENSOR_CONFIG`, `UPDATE_CONFIG_NON_ACTUATING`, `RUN_DEVICE_DIAGNOSTICS`, `PING`, `REPORT_BATTERY`, `CALIBRATION_CHECK`) are processed.

### 2.2 6-Tier Evidence Provenance Guarantee
To guarantee operational integrity and prevent AI hallucination or confusion between synthetic models and real field data, every ingested data point is assigned a strict 6-tier provenance classification:
1. `MEASURED`: Physical reading captured by calibrated physical sensor hardware.
2. `SIMULATED`: Generated by simulation engines (EPANET, WNTR, synthetic physics). If a device is registered as simulated (`is_simulated = True`), the ingestion engine **strictly forbids** `MEASURED` classification and automatically demotes it to `SIMULATED`.
3. `DERIVED`: Computed via deterministic mathematical or hydraulic formulas (e.g., flow rate derived from differential pressure).
4. `PREDICTED`: Inferred by machine learning or statistical forecasting models.
5. `OPERATOR_ENTERED`: Manually inputted by authorized human operators.
6. `UNKNOWN`: Unverified or ambiguous origin.

### 2.3 Modular Sensor Adapter Layer
Sensors report in heterogeneous raw formats, varying engineering units, and varying communication protocols. The `SensorAdapterFactory` resolves specialized adapters implementing `BaseSensorAdapter`:
- `AcousticSensorAdapter`: Normalizes hydrophone noise and decibel acoustic pressure level (dB SPL).
- `PressureSensorAdapter`: Converts psi, kPa, and bar into canonical bar ($1\text{ bar} = 100\text{ kPa} = 14.5038\text{ psi}$).
- `FlowSensorAdapter`: Converts $\text{m}^3/\text{h}$ and $\text{gpm}$ into standard liters per second ($\text{L/s}$).
- `MoistureSensorAdapter`: Normalizes volumetric water content (VWC) into percentage soil saturation.
- `TemperatureSensorAdapter`: Converts Fahrenheit to Celsius ($^{\circ}\text{C}$).
- `OpticalSensorAdapter`: Parses boroscopic inspection clarity metrics and turbidity (NTU).
- `Esp32DeviceAdapter`: Unpacks compound ESP32 IoT telemetry envelopes with link RSSI, battery voltage, and reboot counters.
- `VirtualSensorAdapter`: Ingests synthetic twin telemetry with enforced `SIMULATED` provenance.

## 4. Cross-Module Integration Surface

Task 18 connects seamlessly into existing platform intelligence services:
1. **Task 07 AI Leak Detection**:
   `IotIntelligenceBridge.evaluate_leak_risk_from_telemetry()` evaluates acoustic SPL (dB) and frequency spectrum (Hz) against hydraulic pressure, computing anomaly scores, leak probability, and automated rover dispatch recommendations.
2. **Task 10 Hydraulic Digital Twin**:
   `IotIntelligenceBridge.compare_with_digital_twin()` compares live sensor observations against EPANET baseline simulation curves, flagging hydraulic deviations ($\Delta P$, residual percentage, burst signatures).
3. **Task 16 Repair Planning & Management**:
   `IotIntelligenceBridge.get_sensor_evidence_for_repair()` feeds verified sensor telemetry with explicit calibration badges and provenance chips into damage assessments and post-repair verification workflows.
4. **Task 12 Operational Intelligence**:
   `IotRepository.get_overview_metrics()` exposes IoT fleet status, sensor health, and data quality metrics to the Unified Operational Command Center.

## 5. Architectural Quality Attributes

| Quality Attribute | Architectural Tactic | Implementation |
|---|---|---|
| **Safety** | Air-gap physical actuators | `HARDWARE_ACTUATION_ENABLED = false` rejected with HTTP 403 `HARDWARE_ACTUATION_PROHIBITED` |
| **Security** | Zero-trust authentication | SHA-256 hashed API keys (`aqdev_...`), credential versioning, TLS/mTLS, rate limiting (60 req/min) |
| **Reliability** | Edge store-and-forward | Bounded FIFO ring buffer (1,000 items), exponential backoff with jitter, clock drift estimation |
| **Interoperability** | Standardized HAL adapters | Canonical SI units (bar, L/s, dB, °C, %) via extensible `BaseSensorAdapter` |
| **Data Integrity** | ISO 17025 metrology checks | Overdue calibrations trigger `SUSPECT` or `UNCALIBRATED` data quality tags automatically |
| **Auditability** | Immutable event ledger | Structured `device_audit_logs` recording principal, IP, action, timestamp, and cryptographic key prefix |
